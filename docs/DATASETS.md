# Dataset strategy and provenance

V0.1 contains no real training photographs and no scraped photo corpus. Start with owner-commissioned photographs with written ML/commercial permission, or original 3D scenes with assets whose licenses explicitly permit the intended rendering, training and distribution. Keep camera, lights and architectural mesh fixed while toggling furniture; render paired images, inverse depth, normals and semantic architecture masks. This is a proposed data acquisition strategy, not an existing dataset.

| Candidate | Provenance / pairing | Actual terms and commercial suitability | Decision |
| --- | --- | --- | --- |
| Hypersim | Apple research dataset of artist-authored indoor scenes, rendered RGB, depth, semantics and camera geometry. Standard release is furnished scenes, not ready-made empty/furnished pairs. | Dataset README explicitly specifies **CC BY-SA 3.0**, distinct from software terms. Commercial reuse is possible with attribution and share-alike obligations for adaptations. Underlying scene assets and rendering software have additional terms if re-rendering. Whether a particular model artifact triggers share-alike needs a reviewed release plan. | Useful candidate for geometry/evaluation research. Do not silently remove furniture or assume raw assets are freely redistributable. No data downloaded. |
| Structured3D | Kujiale house designs rendered under different furniture and lighting configurations; empty/simple/full variants can support same-view pairs. Strong layout/depth annotations. | Code is MIT; dataset uses a separate signed Terms of Use. The official Google Drive terms link could not be retrieved in this session. Commercial training permission is **unresolved**, not inferred from MIT code or a third-party mirror. | Quarantine until the owner obtains and reviews the actual data agreement and any commercial grant. No data downloaded or agreement accepted. |
| 3D-FRONT / 3D-FUTURE | Furnished scene layouts and separate furniture assets, potentially renderable twice with fixed cameras. These are not automatically packaged paired photographs. | Separate dataset/asset agreements require checking. Original Alibaba download URL returned 404 during review. Toolbox source availability is not a license for all assets. Commercial grant not established here. | Research lead only; excluded from V0.1 data. |
| Original project fixtures | Two simple geometric room drawings and rectangular furniture targets generated by `scripts/make_fixture.py`. | CC0 dedication in fixture README; no external assets. | Software tests only. Explicit fixture gate prevents accidental use as real training data. |
| Owner-supplied / commissioned pairs | Empty and furnished photographs with fixed camera; photographers/property owner consent as applicable. | Record written permission covering ML training, commercial model use, image retention and redistribution separately. | Preferred commercial dataset path, not yet collected. |

Primary sources reviewed: [Hypersim official repository](https://github.com/apple-aiml-research/ml-hypersim), [CC BY-SA 3.0 actual legal code](https://creativecommons.org/licenses/by-sa/3.0/legalcode.en), [Structured3D official repository](https://github.com/bertjiazheng/Structured3D), [official data layout](https://github.com/bertjiazheng/Structured3D/blob/master/data_organization.md), [official terms link](https://drive.google.com/open?id=13ZwWpU_557ZQccwOUJ8H5lvXD7MeZFMa), [3D-FRONT authors' toolbox](https://github.com/3D-FRONT-FUTURE/3D-FRONT-ToolBox), [authors' paper](https://arxiv.org/abs/2011.09127). Access date: 2026-10-27. Licensing uncertainty is a blocker for ingestion, not a reason to substitute indiscriminate web scraping.

## Manifest format

UTF-8 JSONL, one object per paired example. Paths are relative to the manifest folder, must remain inside it, and must identify local files. See the executable [fixture manifest](../tests/fixtures/manifest.jsonl). Fields:

| Field | Meaning |
| --- | --- |
| `id`, `scene_id` | Unique sample ID and building/scene group for split isolation |
| `split` | `train`, `val`, or `test`; fixed before experiments |
| `input`, `target`, `mask` | Empty room, aligned furnished target, and white-edit mask |
| `prompt` | Style/content description, no private identifying details |
| `license`, `source`, `rights_evidence` | License identifier, provenance, and a durable rights record/reference |
| `commercial_use` | Literal boolean `true` after rights review; this assertion is not legal verification |
| `kind` | `photograph_pair`, `render_pair`, or gated `test_fixture` |
| `sha256` | Object containing content digests for `input`, `target`, `mask` |

`roomcraft validate-manifest` checks required fields, nonempty provenance, content hashes, duplicate IDs, scene leakage, exact-content leakage, decodable images, matching oriented dimensions, edit-mask nonemptiness and path containment. It rejects unknown/unaffirmed commercial rights. Rejected data can remain in a separate quarantine manifest; validation does not modify files.

## Collection and splits

Initially aim for a rights-cleared pilot of 100–500 real pairs or well-rendered pairs, then assess coverage before scaling. These are acquisition targets, not data counts. Split approximately 80/10/10 by building/scene and photographer/project, keeping all camera views, crops and render variants together. Use a held-out test list that training never reads. Maintain a rights ledger and change log, remove duplicates/near-duplicates before splitting, and exclude personal documents, faces and address metadata where possible.

Review mask boundaries, same-camera registration, furniture contact/shadows, architecture invariance and target quality. Domain shift between renders and photographs must be measured. Synthetic pairs need source mesh/asset licenses and renderer settings in provenance. Do not use FLUX-generated images to train competing models contrary to its license.
